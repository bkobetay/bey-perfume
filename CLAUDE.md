# ARAFAN Perfume — инструкции для Claude Code

Сначала прочитай и соблюдай `AGENTS.md`. Работай в этом существующем checkout, сохраняй чужие изменения и историю Git. Общайся с владельцем на русском языке.

## Проект

- Это действующий сайт ARAFAN Perfume: разливная парфюмерия и отдельный раздел оригиналов на распив. Сохраняй текущий бренд и согласованный светлый дизайн с зелёными акцентами.
- В ассортименте 190 позиций с кодами владельца, ценой за миллилитр и объёмами 5/10/20/30 мл. Коды, цены, группы и подтверждённые оценки нельзя произвольно заменять демонстрационными данными.
- Корзина — отдельная страница `/cart`, с доставкой или самовывозом. Счётчик «В корзине» с −/+ находится только внутри карточки аромата; в каталоге остаются иконки корзины и избранного.
- Количественный склад отключён. Продавец управляет заказами, наличием и ценами. Не восстанавливай старую складскую логику по исторической документации.
- Подключение оплаты Kaspi отложено владельцем до завершения остальных работ. Не показывай фиктивную успешную оплату.

## Исходники

- `site/dist/` — витрина на обычных HTML/CSS/JavaScript, без React.
- `site/scripts/storefront.py` — генератор HTML. Изменяй его вместе с генерируемыми страницами и запускай `npm --prefix site run catalog`.
- `site/data/products.json` — канонический каталог; `site/scripts/catalog-enrichment.json` — подтверждённые описания, ноты, фото и источники для повторного импорта.
- `site/dist/cart.js`, `shop-pages.js`, `catalog.js`, `app.js` — корзина, карточки, каталог и общие взаимодействия; `styles.css` и `commerce.css` — стили.
- `site/server/` и `site/scripts/serve.mjs` — локальные API/SQLite и сервер; `site/admin/` — кабинет продавца.
- `site/cloudflare/` — опубликованные Worker/API и миграции D1. Локальные и опубликованные базы и учётные записи раздельные.

## Проверка и запуск

Нужны Node.js >=22.18 и Python 3. Перед запуском проверь занятые порты и существующие процессы: не запускай лишнюю копию сервера.

```sh
npm --prefix site run check
npm --prefix site test
npm --prefix site run catalog
npm --prefix site run dev
npm --prefix site run admin
npm --prefix site run build:pages
```

- Порты по умолчанию: витрина 4173, кабинет продавца 4174. `PORT` и `ADMIN_PORT` позволяют выбрать другие.
- Для текущей разработки использовались 4185/4186 с изолированными данными в `artifacts/store-redesign/private`. `BEY_PRIVATE_DIR` задаёт приватную папку. Сначала проверь актуальные процессы; не сбрасывай данные или пароли без запроса владельца.
- После визуальных изменений проверь браузер, мобильные размеры и отсутствие ошибок. Переходы между страницами и вкладками должны оставаться статичными, без скачков макета или замены шрифта после первого отображения.

## Git и публикация

- Рабочая ветка `codex/homepage-skeleton` отслеживает `origin/main`; remote: `https://github.com/bkobetay/bey-perfume.git`.
- После каждого завершённого логического изменения: `check`, подходящие проверки, просмотр `git diff`, только относящиеся к задаче файлы в staging и содержательный коммит.
- `.githooks/post-commit` автоматически пушит. Проверь, что remote действительно содержит текущий коммит; успешный коммит не означает успешный push. При обычной ошибке исправь причину и повтори `git push --follow-tags`.
- Сохраняй полезные аннотированные checkpoint-теги и локальные diff-файлы в игнорируемой `artifacts/`. Не делай force-push и не переписывай общую историю.
- Push не разрешает новую публикацию. Публикуй изменения только в рамках явного запроса владельца. Для Cloudflare собирай `artifacts/arafan-pages/`, никогда не загружай весь репозиторий. Перед миграциями делай приватную резервную копию.
- Актуальные сведения: `README.md`, `docs/CHANGELOG.md`, `docs/CATALOG-SOURCES.md`, `docs/ARAFAN-CLOUDFLARE.md`. Старые материалы могут описывать уже заменённые бренды и функции.

## Приватные данные

Не коммить, не публикуй и не выводи в чат секреты, данные покупателей, пароли, `.env*`, `.dev.vars*`, `site/private/`, SQLite-файлы и их журналы, резервные копии и OAuth-настройки Wrangler. Не отключай `.gitignore`, Git hooks или защиту приватных путей. Используй существующее хранилище авторизации Git/GitHub CLI и Wrangler, не переноси токены в исходники.

При первом запуске ознакомься с инструкциями и текущим состоянием Git; конкретные изменения сайта выполняй по новой задаче владельца.
