# Проверка этапа 1

Дата: 29 сентября 2026. Среда: macOS, Node.js 26, установленный Google Chrome в headless-режиме через Playwright из среды Codex.

## Проверено

- `npm --prefix site run check`: синтаксис серверного и клиентского JavaScript.
- HTTP 200 для главной страницы; отсутствие ответов 4xx/5xx при её загрузке и взаимодействиях.
- Загрузка локальной иллюстрации, стилей и JavaScript.
- Все шесть вкладок: активное состояние, номер направления и три ноты.
- Клавиатура: стрелки с переходом через край списка, Home и End.
- Мобильное меню: открытие, закрытие Escape, закрытие после перехода к каталогу.
- Якорная ссылка действительно переводит к `#catalog`.
- Отсутствие горизонтального переполнения при ширине 320, 390, 768, 1024 и 1440 px.
- Настройка reduced motion выключает плавную прокрутку.
- Отсутствие ошибок JavaScript и сообщений console.error во время сценария.
- Визуальный просмотр полных скриншотов 1440 px и 390 px; исправлена обрезка флакона на мобильном экране.

Скриншоты: `artifacts/desktop.png`, `artifacts/mobile.png`. Они находятся локально и исключены из Git как проверочные артефакты.

## Повторная ручная проверка

1. Запустить сервер по README и открыть страницу.
2. Проверить переходы из меню и обе кнопки первого экрана.
3. Переключить все направления; проверить изменение описания и нот.
4. Нажать Tab до вкладок, затем стрелки, Home и End.
5. На узком экране открыть меню, закрыть Escape; снова открыть и перейти к разделу.
6. Проверить отсутствие горизонтальной прокрутки, читаемость текста и целостность флакона.
7. Проверить консоль и Network в инструментах браузера.

## Ограничения

Это проверка первого этапа, а не гарантия отсутствия любых ошибок. Физические iPhone/Android и Safari отдельно не тестировались. Реальные коммерческие сценарии не проверяются, поскольку пока не реализованы. Тексты и брендовая иллюстрация требуют согласования перед реальной публикацией.

# Проверка этапа 3 — интерактивный свет

Среда: macOS, изолированный Google Chrome через Playwright; дополнительно просмотр в браузере Codex.

- Проверен синтаксис нового `motion.js`, существующего `app.js` и локального сервера.
- Наведение на первый экран активирует свет; горизонтальное смещение изображения остаётся в пределах 6 px.

- После ухода мыши удаляются активное состояние и inline-параметры наклона.
- Клик по фотоблоку по-прежнему открывает каталог и выбирает «Свежие»; изображение соответствует выбранному направлению.
- Наведение на фотографию направления включает локальный свет и приближение.

- В сенсорном сценарии нет ошибок JavaScript и console.error; визуально просмотрены десктопный первый экран, активный фотоблок и мобильный первый экран.

# Проверка автоматического push

Изолированный временный Git-репозиторий и локальный bare remote, без изменения истории проекта:

- Первый коммит автоматически создаёт удалённую ветку с тем же SHA.
- Синтаксическая ошибка JavaScript блокирует push, но сохраняет локальный коммит.
- Незакоммиченные изменения сайта блокируют отправку версии, которую проверка не покрывает.
- После исправления следующий коммит отправляет накопленную историю.
- Аннотированный checkpoint-тег отправляется с тем же SHA.
- При недоступном remote hook сообщает `PUSH FAILED`, локальный коммит остаётся доступным.
- Синтаксис обоих shell hooks проверен через `sh -n`.

Реальный GitHub remote изначально был пустым: `bkobetay/bey-perfume`. После подтверждённого пользователем входа GitHub CLI настроен credential helper для HTTPS. Первая отправка выполнена: `main` на GitHub и локальный HEAD совпали (`be1c9e50a1a9e92542068087978abda6d337cd98`). Оба тега `checkpoint/v3-before-product-catalog` и `checkpoint/v4-product-catalog` присутствуют на GitHub с исходными SHA. Проверка JavaScript перед push прошла; рабочее дерево после отправки было чистым. Следующий коммит этого отчёта отправляется уже через настроенный post-commit hook.
