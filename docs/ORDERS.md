# Корзина и кабинет продавца

## Локальный запуск

Нужен Node.js 22.18+ (проверено на 26.10). Зависимостей для сервера нет.

```sh
npm --prefix site run admin:setup
npm --prefix site run dev
```

Во втором терминале запустить кабинет:

```sh
npm --prefix site run admin
```

Витрина: `http://127.0.0.1:4173/`. Кабинет: `http://127.0.0.1:4174/` (порт задаётся через `ADMIN_PORT`). Это два отдельных сервиса с общей базой заказов. На адресе магазина `/admin.html`, `/admin.js` и `/api/admin/*` возвращают 404, даже с действующей сессией продавца. Файлы кабинета находятся в `site/admin/`, за пределами публичной папки `site/dist/`. Ссылки на кабинет в магазине нет.
Логин `admin`; случайный пароль создаётся один раз и записывается в `site/private/admin-access.txt`. Повторный `admin:setup` не меняет существующий пароль. Файл не нужно отправлять в переписке или добавлять в Git.

## Путь заявки

1. Клиент выбирает объём 3, 5 или 10 мл и добавляет аромат в корзину.
2. Корзина сохраняет только выбранные товары в браузере; имя и телефон не записываются в localStorage.
3. Клиент вводит имя (буквы, пробел, дефис, апостроф; без цифр и явного мусора) и 10 цифр телефона после закреплённого +7 (маска `700 000 0000`) и разрешает связаться по заявке. Буквы не вводятся; вставка полного номера с +7 или 8 преобразуется в национальный формат. Сервер также требует ровно 10 цифр после +7.
4. Сервер повторно проверяет позиции и рассчитывает сумму по своему списку цен. При расхождении суммы заявка отклоняется с просьбой обновить цены.
5. После записи в SQLite клиент получает код `BEY-…`. Заявка появляется у продавца со статусом «Новый».
6. Продавец находит заявку по коду, имени или телефону, открывает WhatsApp при необходимости, меняет статус и сохраняет заметку. Ссылка WhatsApp подготавливает сообщение на русском и казахском: имя, код заказа, каждый аромат, объём, количество, цена за единицу, сумма позиции, итог и вопрос о подтверждении. Используются цены из сохранённого заказа. Внутренняя заметка не передаётся. Отправка сообщения в WhatsApp остаётся действием самого продавца.

Статусы: Новый → Подтверждён → Собирается → Готов → Выдан; также Отменён. Продавец может исправить статус в обе стороны. Заказы не удаляются. Перемены статуса дополнительно записываются в таблицу `events`. Две вкладки не могут незаметно перезаписать одну версию заказа: устаревшее сохранение получает конфликт.

Вкладки: «В работе», «Новые», «Подтверждённые», «Собираются», «Готовые», «Выданные», «Корзина», «Все». По умолчанию открыта «В работе», без выданных и отменённых. После смены статуса заказ уходит из неподходящей вкладки; «Корзина» хранит отменённые заказы без удаления, их можно восстановить сменой статуса. У вкладок есть счётчики.

Список содержит до 20 заказов на странице. Для обновления нажать «Обновить»; для поиска ввести запрос и нажать Enter или «Обновить». Новые заказы обновляются автоматически каждые 20 секунд, когда кабинет виден и продавец не редактирует карточку или поиск. Автообновление не заменяет несохранённые заметки. Кабинет предупреждает о несохранённых правках перед обновлением списка/уходом.

## Цены и контент

Все текущие цены **демонстрационные**, в KZT; это обозначено на карточках и в корзине. Изменить `variants` у товара в `site/data/products.json`, затем:

```sh
npm --prefix site run catalog
npm --prefix site run check
```

После изменения исходных цен перезапустить сервер. Заказ сохраняет снимок названий, объёмов и цен на момент оформления; следующие изменения каталога не меняют старые заказы. При недоступном сервере добавление в корзину отключено. При ошибке отправки позиции остаются; повтор неизменённого запроса в открытом окне не создаёт второй заказ. Перезагрузка страницы после неоднозначного сетевого сбоя не восстанавливает контактные поля и идентификатор запроса — в этом случае продавец должен проверить, не пришла ли заявка ранее.

## Приватные данные и резервная копия

- `site/private/orders.sqlite` — заказы, история статусов и хеши сессий.
- `site/private/admin.json` — соль и scrypt-хеш пароля.
- `site/private/admin-access.txt` — локальная памятка с паролем.
- `site/private/backups/` — локальные копии.
- Папка имеет права 700, приватные файлы — 600. Папка находится за пределами публичной `dist/` и исключена из Git, как `.env`, ключи и файлы SQLite.
- Pre-push проверяет текущий коммит и ещё не отправленную историю на приватные пути (включая файл, удалённый следующим коммитом). Это дополнительная защита от случайной отправки, а не универсальный поиск секретов внутри произвольных файлов.
- `.gitignore` содержит только правила исключения. Его нужно хранить в Git, чтобы другие копии проекта тоже исключали приватные файлы.
- Игнорирование секретов не скрывает исходники публичного GitHub-репозитория; приватность репозитория — отдельная настройка.

Создать согласованную копию работающей базы:

```sh
npm --prefix site run orders:backup
```

Копия остаётся в `site/private/backups/`, содержит персональные данные и не отправляется в GitHub. Git-checkpoint сохраняет код, **не базу заказов**. Для восстановления: остановить сервер, сохранить всю текущую папку `site/private/` отдельно, заменить базу выбранной копией и убрать соответствующие старые WAL/SHM файлы из рабочей папки (сохранить их вместе со старой базой), затем запустить сервер. Не копировать один SQLite-файл поверх работающего сервера.

## Границы демоверсии

Это локальная демонстрация: сервер слушает только `127.0.0.1`, оплаты, доставки, складского учёта и уведомлений нет. Доступ к API заказов защищён парольной сессией; отсутствие ссылки на кабинет в меню само по себе защитой не считается. Пароль хешируется scrypt, cookie имеет HttpOnly/SameSite=Strict, срок сессии — 8 часов, есть ограничение попыток входа, проверка Origin/Host и размера запроса. Заголовки запрещают встраивание сайта в iframe и загрузку внешних скриптов.

При публикации магазин и кабинет получат отдельные интернет-адреса с общей базой; VPN для продавца не требуется. Адрес кабинета не рекламируется в магазине, но его секретность не заменяет пароль. До публичного размещения нужны HTTPS (включая Secure-cookie), отдельная настройка домена/Origin, резервное копирование за пределы этого Mac, реальные цены и условия обработки клиентских данных. Здесь HTTP используется только на loopback; простое открытие порта наружу не является поддерживаемым запуском.

Технические источники: [Node.js SQLite](https://nodejs.org/api/sqlite.html), [OWASP — управление сессиями](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

## Обзоры ALISH

`site/data/reviews.json` содержит до 50 записей: `id`, `title`, `topic`, `visual` (`ritual`, `bottle`, `notes`) и `url`. Допустимы только HTTPS-ссылки Instagram/TikTok. При `url: null` карточка честно помечена «Скоро» без кнопки воспроизведения.

```sh
npm --prefix site run reviews
```

Генератор оставляет на главной первые три карточки, остальные помещает на `/reviews.html`. На странице обзоров поиск и по 12 карточек на странице. Поиск и страница сохраняются в URL. Подключены три присланных MP4. Для локального видео используются поля `video`, `poster`, `duration`; файлы лежат в `site/dist/assets/reviews/`. Плеер загружает MP4 только после нажатия и освобождает его при закрытии. HTTP Range поддерживает перемотку. Веб-копии используют H.264 + AAC-LC и faststart; исходные файлы сохранены в Downloads. Стеклянные контролы поддерживают паузу, перемотку, звук, полный экран и повтор загрузки. Внешние ссылки Instagram/TikTok по-прежнему поддерживаются.

Проверка имени проверяет формат, повторы, смешение раскладок внутри слова и ограниченный список очевидных случайных наборов. Это не проверка личности и не полный словарь существующих имён: редкие имена, казахские буквы и другие письменности не исключаются. Проверка общая для браузера и сервера.

## Склад и наличие

В кабинете продавца появился раздел **Склад**. Остаток каждого аромата хранится в общей SQLite-базе с точностью 0,1 мл. По согласованию для первого запуска выставлено **по 100 мл каждого из восьми ароматов**; перед реальными продажами продавец вводит фактические остатки. После перезапуска они сохраняются. Для добавленных позднее новых ароматов начальный остаток — 0 мл.

Доступны операции:

- **Поступление** — прибавить объём нового флакона.
- **Списание** — уменьшить остаток, например из-за тестеров или потерь.
- **Установить остаток** — указать фактический объём после пересчёта.

У каждой операции обязательный комментарий. История показывает последние 50 изменений, объём, остаток после операции, дату и код заказа для связанных списаний/возвратов. Изменение из устаревшей вкладки отклоняется, чтобы не потерять другое поступление или продажу. Повторная отправка одной операции не применяет её дважды.

Новая заявка не резервирует и не списывает объём. При переводе в «Подтверждён», «Собирается», «Готов» или «Выдан» продавец отмечает **«Оплата проверена»**. Сервер суммирует `мл × количество` по каждому аромату, включая разные объёмы одного аромата. Списание и статус сохраняются в одной транзакции; если любого объёма не хватает, ничего не списывается и статус не меняется. Повторное подтверждение, смена заметки и движение между последующими статусами не списывают объём заново.

При отмене подтверждённого заказа списание сохраняется. Когда товар фактически возвращён, продавец нажимает **«Вернуть объём на склад»** в отменённом заказе. Повторный возврат блокируется. Если возвращённый заказ снова подтверждается, объём повторно проверяется и списывается.

Заказы, уже вышедшие из статуса «Новый» до включения склада, помечаются как созданные до учёта: прошлые продажи автоматически не вычитаются из начальных остатков. Для них начальный остаток нужно сверить вручную.

Магазин обновляет наличие при открытии страницы, возвращении во вкладку и каждые 20 секунд в видимой вкладке. Недоступные варианты объёма отключены; если нет ни одного доступного объёма, отображается **«Нет в наличии»**. Корзина учитывает суммарный объём всех вариантов, а API повторно проверяет наличие при отправке заявки и подтверждении продавцом. Лишь открытая корзина или новая заявка не гарантируют резерв.

Склад доступен только через авторизованный `/api/admin/inventory` на сервисе продавца. Публичный `/api/products` отдаёт наличие без журнала операций. База и резервные копии остаются в `site/private/` и не попадают в Git.
